JIRA بديل للعالم الحر

HelixTrack هو بديل شامل وحديث ومفتوح المصدر لـ JIRA (وبواسطة امتداده "المستندات"، لـ Confluence أيضاً) — نظام متعدد المنصات لإدارة المشاريع وتتبع المشكلات، مبني على خلفية Go للخدمات المصغرة مع عملاء أصليين للويب وسطح المكتب والهواتف المحمولة.

بديل مفتوح المصدر لـ JIRA/Confluence. توفر خلفية Go للخدمات المصغرة ("HelixTrack Core") واجهة REST API موحدة لتتبع المشاريع والمشكلات، بالإضافة إلى مساحة عمل وثائقية على نمط Confluence، تُقدَّم للعملاء الأصليين للويب وسطح المكتب وأنظمة Android وiOS عبر HTTP/3 QUIC.

HelixTrack هو منصة مفتوحة المصدر لإدارة المشاريع وتتبع المشكلات، تُقدَّم كبديل للعالم الحر لـ JIRA وConfluence — بديل كامل للمنتجين اللذين تعتمد عليهما معظم المؤسسات الهندسية، أُعيد بناؤهما كبرنامج تملكه ويمكن تشغيله في أي مكان. في قلب النظام يوجد HelixTrack Core، خدمة مصغرة مكتوبة بلغة Go باستخدام إطار عمل Gin، توفر تتبعاً كاملاً للمشكلات، لوحات أجايل وسكرم، إدارة الفرق، ونظام أذونات هرمي يمكن تبديل تنفيذه بين محرك داخلي محلي وخدمة مدعومة بـ HTTP — مما يسمح لنموذج التفويض نفسه بالتوسع من حاسوب محمول واحد إلى مجموعة موزعة دون تعديل كود التطبيق. بدلاً من نشر واجهة REST عبر عشرات المسارات، يوجّه Core كل شيء عبر نقطة نهاية واحدة /do موجهة بالإجراءات، مع نموذج طلب/استجابة موحد (action/jwt/object/data للداخل، errorCode/errorMessage/data للخارج): كل عميل يتحدث نفس العقد الصغير، وإضافة ميزة تعني إضافة إجراء، وليس URL جديداً لتوثيقه وتأمينه وإصداره.

يتكامل Core مع خدمات مصممة لفصل المصادقة والأذونات والترجمة، تتواصل عبر HTTP/3 QUIC ويمكن تشغيلها على أجهزة أو مجموعات منفصلة، أو تعطيلها بالكامل في بيئات الاختبار. تُخزن البيانات في SQLite لتطوير سهل وبدون إعدادات، وفي PostgreSQL للإنتاج، وتُشفَّر أثناء التخزين باستخدام SQLCipher (AES-256) بحيث تُحمى بيانات المشاريع الحساسة على القرص افتراضياً وليس كإجراء لاحق. يمكّن امتداد Documents V2 من تحويل المتتبع إلى منصة معرفية كاملة: مساحة عمل على نمط Confluence تتضمن مساحات وصفحات ومراقبة الإصدارات وقوالب وتعاوناً فورياً عبر WebSocket وتحليلات — حيث يلتقي الويكي ومتتبع المشكلات أخيراً خلف خلفية واحدة بدلاً من منتجين مدمجين معاً.

حول Core توجد عدة تطبيقات عملاء: عميل ويب Angular، وعميل سطح مكتب Tauri + Angular، وتطبيقات أصلية لنظامي Android (Kotlin) وiOS (Swift)، بالإضافة إلى عملاء لأنظمة HarmonyOS وAurora OS وحافظة شاشة — كلها تتواصل مع نفس الخلفية وتكتشفها تلقائياً على الشبكات المحلية عبر بث UDP، بحيث يجد العميل الجديد خادمه دون الحاجة إلى تهيئة يدوية. تُدار تطبيقات العملاء كمستودعات منفصلة وخاصة وتُعرض هنا على مستوى المنتج فقط.

المحتوى

لنقّدم للفرق بديلاً مفتوح المصدر وقابلاً للاستضافة الذاتية حقاً عن حزمة JIRA + Confluence — "من أجل العالم الحر" — دون قيود البائعين، يجمع بين تتبع المهام والمستندات والتعاون المؤسسي تحت ترخيص مفتوح واحد.

إنها تدمج منتجين تجاريين ثقيلين — تتبع المشكلات وحزمة الويكي/المستندات — في منصة واحدة مفتوحة وعالية الأداء وقابلة للاستضافة الذاتية، وتضيف إليها ما لم تقدمه الحلول الحالية قط: عملاء أصليون حقيقيون عبر منصات متعددة (الويب، سطح المكتب، أندرويد، آي أو إس، بالإضافة إلى HarmonyOS وAurora OS)، جميعها مدفوعة بعقد خلفي واحد. المفتاح هنا هو الملكية دون تنازلات. تصميم HTTP/3 اللامتمركز بالكامل مع خدمات مصغرة منفصلة، وتشفير SQLCipher AES-256 أثناء التخزين، يوفران الأداء والأمان اللذين عادةً ما يقتصران على الخدمات السحابية الخاصة، لكن في نظام تستضيفه بنفسك — دون تراخيص مقاعد، ودون قيود البائعين، ودون مغادرة بياناتك لبنيتك التحتية. تحصل الفرق على تجربة JIRA-plus-Confluence التي تعرفها بالفعل، على أجهزتها الخاصة، وتحت ترخيص مفتوح المصدر واحد.

  • واجهة /do API الموحدة القائمة على الإجراءات — نقطة نهاية واحدة، حاوية واحدة، توجيه بناءً على الإجراء. تصل القدرات الجديدة كأفعال جديدة، لا عناوين URL جديدة، مما يقلص سطح الهجوم، وكود العميل، وأعباء التوثيق إلى عقد واحد تشترك فيه جميع المنصات.
  • HTTP/3 QUIC كنقل افتراضي بين الخدمات — شبكات حديثة منخفضة الكمون ومرنة في الاتصالات بين الخدمات منذ اليوم الأول، لا تُضاف لاحقاً.
  • محرك أذونات قابل للتبديل بين تنفيذ محلي داخل العملية وخدمة مدعومة بـ HTTP، إلى جانب خدمات المصادقة والأذونات والتوطين القابلة للنشر بشكل مستقل — نفس نموذج التفويض سواء كنت تشغل عملية واحدة أو مجموعة خوادم.
  • عزل البيانات عبر مساحات متعددة باستخدام علامة --space-root: يحصل كل مشروع على قاعدة بيانات ومخزن أصول معزولين، بحيث تُفصل المستأجرون والمشاريع عند حدود التخزين بدلاً من استخدام عوامل التصفية في الاستعلامات.
  • تشفير SQLCipher AES-256 أثناء التخزين — حماية بيانات المشاريع الحساسة على القرص بشكل شفاف، افتراضياً.
  • الاكتشاف التلقائي للعميل إلى الخادم عبر بث UDP على الشبكات المحلية — يكتشف العميل Core دون أي تهيئة يدوية.
  • المستندات V2، بديل حقيقي لـ Confluence، مع تحرير متوازٍ بتقنية القفل المتفائل، وكشف التعارضات، وسجل كامل للتغييرات — مستندات تعاونية حقيقية تعيش خلف نفس الخلفية مع أداة التتبع.

  • ست منصات عميل، خلفية واحدة، انحراف صفري في العقد. الحفاظ على عملاء الويب/Angular وسطح المكتب/Tauri وأندرويد/Kotlin وآي أو إس/Swift وHarmonyOS وAurora يعني عادةً ست عمليات تكامل API متباينة تتآكل بشكل غير متزامن. لقد ألغينا هذا الخطر بجعل واجهة /do API القائمة على الإجراءات وحاويتها الثابتة العقدة الوحيدة — يستهدفها كل عميل بنفس الطريقة — وأضفنا فوقها اكتشاف الخدمة عبر بث UDP حتى يتمكن العملاء من تحديد موقع Core على الشبكة دون تهيئة يدوية للنقاط النهائية.
  • فصل الخدمات دون دفع ضريبة الكمون. تقسيم خدمات المصادقة والأذونات والتوطين إلى خدمات قابلة للنشر بشكل مستقل يضيف عادةً قفزة شبكية لكل استدعاء. اعتمدنا HTTP/3 QUIC عبر جميع الاستدعاءات بين الخدمات للحفاظ على سرعة هذه القفزات ومرونة الاتصالات، وجعلنا كل خدمة قابلة للتشغيل بشكل مستقل — حتى تعطيلها بالكامل في تكوينات الاختبار — بحيث يكون الفصل خيار نشر، لا تكلفة ثابتة.
  • التعاون بمستوى Confluence دون فوضى الكتابة المفقودة. التحرير المتعدد المؤلفين في الوقت الفعلي يفتح الباب أمام تعارضات الكتابة. تحل المستندات V2 هذه المشكلة بمساحات/صفحات/إصدارات تحت قفل متفائل بالإضافة إلى كشف التعارضات الصريح، وسجل كامل للتغييرات للعودة إليه، ومزامنة WebSocket في الوقت الفعلي — تعاون يظل متسقاً بدلاً من محو التعديلات بصمت.
  • التشفير أثناء التخزين دون قتل الإنتاجية. يحمي SQLCipher AES-256 البيانات على القرص لكنه يضيف عبئاً لكل استعلام؛ عوضنا ذلك بالتخزين المؤقت متعدد الطبقات (LRU في الذاكرة أمام Redis في خدمة التوطين) بحيث تظل المسارات الساخنة مثل عمليات البحث متعددة اللغات سريعة بينما تبقى البيانات مشفرة.

المحتوى

  • Go + Gin — اختيرت لبناء خدمات HTTP عالية الإنتاجية ومنخفضة الكمون مع إمكانية النشر عبر ثنائي واحد؛ تتضمن نواة REST API، وبرنامجها الوسيط JWT/CORS، وجهاز التوجيه /do الذي يتصدر النظام بأكمله.
  • HTTP/3 QUIC — اختير كوسيلة نقل بين النواة وخدمات المصادقة والأذونات والتوطين، حيث يقلل تصميم QUIC المتعدد القنوات والمهاجر للاتصالات من زمن الاستجابة الطويل ويتحمل الروابط غير المستقرة التي تتعطل فيها TCP.
  • PostgreSQL (الإنتاج) / SQLite (التطوير) — نموذج علائقي واحد يدعم مخطط التتبع والمستندات الكبير عبر كلا المحركين: يبقي SQLite التطوير المحلي خالياً من الإعدادات ويعتمد على الملفات، بينما يتولى Postgres الإنتاج بمقياس واسع عبر ملف تكوين production مخصص.
  • SQLCipher (AES-256) — اختير للتشفير الشفاف على مستوى قاعدة البيانات أثناء السكون، مما يحمي البيانات الحساسة للمشاريع دون الحاجة إلى تشفير على مستوى التطبيق أو تغيير طريقة كتابة الاستعلامات.
  • Redis — اختير كطبقة ذاكرة تخزين مشتركة خلف ذاكرة تخزين مؤقتة LRU داخل خدمة التوطين، مما يوفر طبقة تخزين مزدوجة تحافظ على سرعة عمليات البحث متعددة اللغات حتى مع عبء التشفير تحتها.
  • Uber Zap + Lumberjack — اختيرا لتسجيل البيانات المنظّم وخفيف التخصيص مع دوران تلقائي للسجلات، مما يحافظ على قابلية مراقبة النواة في الإنتاج دون نمو غير محدود للسجلات.
  • golang-jwt / JWT — اختيرا كآلية مصادقة عديمة الحالة؛ يحمل الرمز المميز الموقع في حقل jwt بكل مظروف /do، مما يضمن توحيد المصادقة عبر جميع العملاء.
  • Angular 19 (+ Material، RxJS) — اختير لبناء عميل متصفح تفاعلي قائم على المكونات مع نظام تصميم Material ناضج جاهز للاستخدام مباشرة.
  • Tauri 2.0 + Rust + Angular — اختير لإصدار واجهة سطح مكتب أصلية بحجم صغير عبر إعادة استخدام واجهة Angular داخل عرض ويب مدعوم بـ Rust بدلاً من تضمين بيئة متصفح كاملة.
  • Kotlin (أندرويد) / Swift + SwiftUI (آي أو إس) — اختيرا لتقديم عملاء أصليين ومتوافقين مع منصات الهواتف بدلاً من عرض ويب مغلف.
  • Docker / Docker Compose (متوافق مع Podman) — اختير للنشر القابل للتكرار والحاوي عبر الحاويات مع تفعيل فحوصات /health، والتوافق مع Podman بحيث لا يتطلب أي خدمة خلفية أو بائع محدد.
  • Testify (Go)؛ Cypress/Playwright/Karma+Jasmine (العملاء) — اختير للاختبار الآلي متعدد الطبقات الذي يغطي عقد الواجهة الخلفية وواجهات المستخدم للعملاء بشكل مستقل، بما يتوافق مع بنية نواة واحدة وعدة عملاء.

  • الحالة: تجريبية. نواة HelixTrack هي خدمة REST API مصغرة عاملة؛ يُوثّق امتداد المستندات V2 بأنه مكتمل بنسبة 95% تقريباً مع وجود مشكلة معروفة في تعيين حقول قاعدة البيانات، لذا لا يُقدّم على أنه مكتمل تماماً.
