チーム向けゼロトラスト端末プラットフォーム — すべてのSSHセッションを保護し、共有し、AIによる支援を提供

HelixTerminatorは、企業向け端末およびSSHセッション管理プラットフォームであり、Goマイクロサービスシステムとして構築され、クロスプラットフォームのFlutterクライアントを備えています。ゼロトラストモデルの下でリモートセッションの仲介、記録、保護を行い、リアルタイムでの共同作業を可能にし、端末上にAI支援機能を重ね合わせます。

HelixTerminatorは、ゼロトラストを基盤とした企業向け端末／SSH管理プラットフォームです。Goマイクロサービスのバックエンドと、6つのプラットフォームに対応したFlutterクライアントで構成されています。ホストの管理、接続の仲介、セッションの記録、リアルタイムでの共同作業を実現し、AIによるコマンドヘルプ、出力の解説、インシデント対応機能を提供します。

HelixTerminatorは、企業向け端末およびリモートアクセスプラットフォームであり、2つのモジュール（端末プラットフォームと接続仲介）で構成され、Goマイクロサービス群を基盤とし、6つのプラットフォームを対象とした単一のFlutterクライアントを備えています。その目的は、場当たり的なSSHツールを完全に置き換えることにあります。個々のラップトップ向けクライアントや秘密鍵の散乱、監査の抜け穴はなくなり、代わりにリモートアクセスを個人の習慣ではなくインフラとして扱う、統制された監査可能で共同作業に対応したシステムが提供されます。

バックエンドは、リモートアクセスのライフサイクル全体を一元管理します。ホストとグループはバスティオン／ジャンプホストチェーンで管理され、SSHプロキシがパスワード、公開鍵、証明書認証を仲介。端末I/OプロキシがセッションをWebSocket経由でストリーミングし、SFTPが再開可能な転送を処理。さらにポートフォワーディング、スニペットやワークスペースの管理、セッションの録画機能が統合され、署名付きasciinema再生で信頼性の高い再生が可能です。セキュリティは後付けではなく、ゼロトラスト設計を採用：Vaultによるゼロ知識の秘密情報保管、PKIサービスによる短命なSSH証明書の発行（盗難リスクのある永続的な認証情報は存在しない）、ハードウェアバックアップ鍵チェーン（Secure Enclave／Android Keystore／DPAPI／HSM）によるディスク外鍵管理、FIDO2／WebAuthnやOIDC／SAMLによる認証、改ざん検知可能な追記専用Merkleチェーン監査ログによるSOC 2／ISO 27001対応証跡の生成。さらに、リアルタイムでの共同作業機能により、複数のオペレーターが1つのライブセッションを観察者／副操縦士／所有者の役割で共有でき、CRDTバッファ同期により一貫性が保たれます。

端末自体にはAIサービスが組み込まれ、コマンドの自動補完、出力の平易な解説、異常検知、ランブック生成、インシデント時の実践的支援を提供。端末を単なる通信経路から、重要な瞬間に役立つアシスタントへと進化させます。プラットフォーム全体はコンテナネイティブで、Kubernetes、Helm、Terraform、そしてOpenTelemetry、Grafana、Jaeger、Lokiによる完全なオブザーバビリティスタックを備えています。また、HelixTrackブリッジとローカルのHelixLLMを通じて、より広範なHelixファミリーと連携。すべてはHelixのConstitutionの下で動作し、なりすまし防止のための継承検証ゲートが実装されています。

コンテンツ

チームは分散したSSHクライアントを通じてリモートインフラを運用していますが、共通の監査証跡もなく、シークレットの一貫した管理もできず、インシデント発生時にリアルタイムで共同作業を行う手段もありません。HelixTerminatorは、リモートアクセスを個々のラップトップ向けツールから、ガバナンスに基づくゼロトラストのチームネイティブなプラットフォームへと進化させるために開発されました。

HelixTerminatorは、従来の調達リストを一つのプラットフォームに統合します。SSHクライアント、シークレットボールト、バスティオン/PKIレイヤー、セッション記録、コンプライアンス監査、リアルタイムコラボレーション――これらは通常、チームが個別に購入し、連携させ、調整しなければならないもので、それぞれの接合部には必ずギャップが生じます。HelixTerminatorはこれらを一つのガバナンスされたシステムとして提供し、さらに、どのツールも単独では実現できない機能を備えています。それは、ターミナル上に直接AIレイヤーを重ね、インシデント発生中に未知の出力を解説し、ランブックを自動生成するというものです。これまで実現不可能だった機能――ゼロトラストで保護され、改ざん検知可能な記録が残り、複数のオペレーターでリアルタイム共有され、AIの支援を受けられるリモートアクセスセッションが、一つの画面で同時に実現します。

  • デュアルモジュール設計（ターミナルプラットフォーム＋コネクションブローカー）をサービスレジストリで連携させ、プラットフォームとブローカーレイヤーが独立してスケール・進化できる構造。
  • エンドツーエンドのゼロトラストセキュリティ：PKIが発行する短命なSSH証明書、ゼロ知識ボールト、ハードウェアバックアップのキーチェーン、そしてマークルチェーンによる監査ログを採用。長期的な認証情報は一切なく、改ざん不可能な証跡を確保。
  • リアルタイムセッションコラボレーション：CRDTベースのバッファ同期と明確なオブザーバー／コパイロット／オーナーの役割分担により、複数のオペレーターが一つのターミナルを操作しても競合しない。
  • AI支援によるオペレーション：ライブターミナルに直接重ねられた支援機能で、オートコンプリート、出力解説、異常検知、ランブック／インシデント支援をオペレーターの必要なタイミングで提供。
  • クロスプラットフォームFlutterクライアント：単一のコードベースから6つのプラットフォームを駆動し、デスクトップ、モバイル、ウェブのエクスペリエンスを完全に同期。

  • 盗まれる可能性のある長期認証情報を一切持たずにリモートアクセスを保護する――長期的な鍵は典型的な侵害の原因（vector）です。この課題は、オンデマンドで短命なSSH証明書を発行するPKIサービス、サーバー自身も読み取れないシークレットを保持するゼロ知識ボールト、そしてハードウェアバックアップのキーストレージ（Secure Enclave／Android Keystore／DPAPI／HSM）を採用することで解決。秘密情報がディスク上に露出することはありません。
  • 複数のオペレーターが一つのセッションを操作してもバッファが破損しないようにする――共有ターミナルへの同時編集は、整合性の確保が難しい問題です。この課題は、CRDTベースのバッファ同期を採用することで解決（ADR-006に基づき、中央の調停者なしで収束可能なCRDTをオペレーショナルトランスフォーメーションに優先）。
  • コンプライアンス証跡を密かに改ざんできないようにする――編集可能な監査ログは証拠として無意味です。この課題は、追記専用かつマークルチェーン化されたログを採用することで解決。改ざんがあればハッシュチェーンが破壊され、SOC 2／ISO 27001／FedRAMPに準拠したエクスポート可能な証跡を生成します。
  • デスクトップ、モバイル、ウェブで一貫したUXを実現しつつ、3つのコードベースを持たない――この課題は、BLoCパターンに基づく単一のFlutter／Dartクライアントを採用することで解決（ADR-001に基づき、ElectronよりもFlutterを優先し、一つのソースから6つのプラットフォームをカバー）。

コンテンツ

  • Go マイクロサービス — バックエンド群（SSH プロキシ、ターミナル、Vault、PKI、監査など）。並行処理モデルと小さなランタイムフットプリントが特徴で、多数の長時間ストリーミングセッションを同時に保持するサービスに最適（ADR-002: Rust/Node に対する Go の採用）。
  • Flutter / Dart（BLoC） — 6つのプラットフォームで共通のクライアントコードベース。BLoC により状態管理の予測可能性を確保。Electron ではなく Flutter を選定（ADR-001）し、ネイティブとウェブのフロントエンドを別々にメンテナンスする手間を回避。
  • PostgreSQL — 主要データストア。CockroachDB ではなくこちらを採用（ADR-004）し、成熟したトランザクショナルコアを確保。
  • Kafka + RabbitMQ — セッションセグメントやイベントを伝送するメッセージング・ストリーミング層（ADR-003）。耐久性のあるログと柔軟なキューイングを組み合わせ。
  • Redis — ターミナルのスクロールバックバッファやホットセッションの状態を保持。耐久性よりも低レイテンシのアクセスが重視される場面で使用。
  • SPIFFE/SPIRE + mTLS — 暗号化されたワークロードIDを発行（ADR-005）。サービス間通信を相互認証し、メッシュ内部にゼロトラストを拡張（エッジだけでなく）。
  • Ed25519（EdDSA） — JWT やセッション記録に署名（ADR-009）。高速かつ最新の署名方式により、記録されたセッションの検証を可能に。
  • Kubernetes + Helm + Terraform — コンテナネイティブなデプロイメントと、再現性のあるバージョン管理されたインフラ（ADR-007/008）。
  • OpenTelemetry、Grafana、Jaeger、Loki — トレース、メトリクス、ダッシュボード、ログのためのオブザーバビリティスタック。Falco、Trivy、Cosign、Sealed Secrets — ランタイム脅威検知、イメージスキャン、アーティファクト署名、サプライチェーン全体での暗号化シークレット配信。

  • ステータス: ベータ版。大規模で積極的に開発中のコードベース（2026年7月4日作成）。プロジェクトのMVPリサーチパッケージに記載された数値仕様（エンドポイント、テーブル、サービス数など）は、docs/research/mvp/ にある設計・仕様上の目標値であり、完全に実装されているとは限りません。そのため、上記では「出荷済みの実績」ではなく「アーキテクチャのスコープ」として提示しています。レイテンシ/SLOや「プロダクションレディ」の主張は、第三者による検証を受けていません。
  • ライセンス: Apache-2.0（GitHub API に準拠）。
