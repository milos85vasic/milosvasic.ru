01 — AIエンジニアリング

AIエンジニアリング

LLMインフラ、自律エージェント、そしてそれらを信頼に足るものにするガバナンス。

production AI systems with verifiable behaviour

プロフィール

本番環境のAIシステムの信頼性は、自らを信用しない部分をどれだけ持っているかで決まります。単一プロバイダーを前提とした抽象化は賭けであり、自律エージェントは制御プレーンであり、ガバナンスこそがエージェント群の逸脱を防ぐ唯一の手段です。この分野で私は、その3つすべてを構築しています。フォールバックをハードコードせずに43のプロバイダーを束ねるLLMレイヤー、ヘッドレスCLIエージェントを起動して駆動する自律的な制御プレーン、そして「Do you see my code?」ゲートによって、実際に動作すると証明されたモデルだけを利用可能としてマークし、エクスポートする検証レイヤーです。

HelixAgent

単一のモデルを信用しない、本番グレードのアンサンブルLLMサービス。AI/LLM、Go、Gin、PostgreSQL、Redis、サーキットブレーカー、ヘルスモニタリング。

LLMProvider

43のプロバイダーを1つのインターフェースで扱えます。ジッター付きバックオフによるリトライと、フォールバックをハードコードせず実際に利用可能なモデルだけを探索する仕組みを備えています。

HelixLLM

1つのバイナリで6つのデプロイモード。HTTP/3上でOpenAI互換・Anthropic互換の推論を提供し、ノートPCからマルチホストクラスターまでスケールします。

主なプロジェクト

  • HelixAgent flagship Go, Gin, PostgreSQL, Redis, Prometheus, OpenTelemetry, Neo4j, ClickHouse, Kafka

    単一モデルを信用しない、プロダクショングレードのアンサンブルLLMサービス。プロンプトを多数のプロバイダーに展開し、構造化された複数ラウンドの議論（Proposal → Critique → Review → Synthesis）を行い、リアルタイムの検証スコアに基づいてルーティングし、適切にフォールバックする。HA対応のデータ層、オブザーバビリティ、ガードレールを備えたOpenAI互換APIとして提供。

  • HelixCode flagship Go, Gin, PostgreSQL, Redis, SSH, MCP, llama.cpp

    依存関係を考慮してタスクを分割し、SSH管理のワーカー群に分散させる分散AI開発プラットフォーム。チェックポイントとロールバックにより、タスクが中断されても何も失われない。ハードウェアを考慮したモデル選択と、plan/build/test/refactorの全ライフサイクルをREST、CLI、TUI、MCPから利用できる。

  • HelixLLM flagship Go, HTTP/3 QUIC, gRPC, SSE, Kafka, llama.cpp

    1つのバイナリ、6つのデプロイモード：ノートPCからマルチホストクラスターまでスケールする、HTTP/3上のOpenAI／Anthropic互換推論サーバー。llama.cpp（CUDA/Metal/ROCm）によるローカル推論と、検証スコアに基づき自動検出されるクラウドのフォールバックチェーンを備え、最終的には必ず、確実に動作するローカルモデルへ縮退（フォールバック）する。

  • LLMProvider core Go, Circuit Breakers, Health Monitoring

    43のプロバイダーを1つのインターフェースで扱う。サーキットブレーカー、ヘルスモニタリング、ジッター付きバックオフのリトライ、ハードコードされたフォールバックに頼らない実態に即した正確なモデル検出を備える。

  • LLMOrchestrator core Go, Pipe Protocol, CLI Agents

    ヘッドレスCLIエージェント（OpenCode、Claude Code、Gemini、Junie、Qwen Code）を起動・制御する、スレッドセーフなコントロールプレーン。パイプとファイルのハイブリッドプロトコルを使用。

  • LLMsVerifier core Go, Verification, Benchmarking

    「Do you see my code?」ゲートを必須とする検証の信頼できる情報源。実際に動作すると証明されたモデルだけが、利用可能としてマークされ、エクスポートされる。

応募の件

LLM infrastructure, autonomous agents, and the governance that makes them trustworthy.

production AI systems with verifiable behaviour

HelixAgent

A production-grade ensemble LLM service that refuses to trust a single model: it fans a prompt across many providers, runs structured multi-round debate (Proposal → Critique → Review → Synthesis), and routes by live verification scores with graceful fallback — behind an OpenAI-compatible API with an HA data layer, observability and guardrails. Stack: Go, Gin, PostgreSQL, Redis, Prometheus, OpenTelemetry.

HelixCode

A distributed AI development platform that divides work into dependency-aware tasks across an SSH-managed worker fleet, then checkpoints and rolls back so nothing is lost when a task is interrupted — with hardware-aware model selection and a full plan/build/test/refactor lifecycle behind REST, CLI, TUI and MCP. Stack: Go, Gin, PostgreSQL, Redis, SSH, MCP.

HelixLLM

One binary, six deployment modes: OpenAI- and Anthropic-compatible inference over HTTP/3 that scales from a laptop to a multi-host cluster, with local llama.cpp inference (CUDA/Metal/ROCm) and an auto-discovering, verification-scored cloud fallback chain that always degrades to a guaranteed local model. Stack: Go, HTTP/3 QUIC, gRPC, SSE, Kafka, llama.cpp.

LLMProvider

One interface over 43 providers with circuit breakers, health monitoring, jittered-backoff retries and honest, no-hardcoded-fallback model discovery. Stack: Go, Circuit Breakers, Health Monitoring.

Across these projects my focus is AI / LLM systems, Engineering governance — and the same discipline carries into everything I ship.
